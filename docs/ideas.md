# Ideas (out of scope for now)

Ideas that came up during the work but aren't part of the current roadmap.

- **SegFormer sliding-window eval** (from C1): evaluate SegFormer-B0 at 1024×2048 with 1024×1024 sliding windows, as in the paper, to test whether whole-image inference explains the 1.8-point gap to the published 76.2. Not needed for deployment (we run whole-image at 512×1024).
- **Per-layer parity against PyTorch** (from C2, D-012): map ONNX tensors to PyTorch module outputs through the dynamo exporter's `pkg.torch.onnx.name_scopes` node metadata and capture them with forward hooks. Would localize bugs introduced by the export itself; not needed while whole-model torch↔ORT parity passes.
- **ModelOpt vs ORT quantization** (from C3, D-015): quantize both models with NVIDIA ModelOpt's ONNX PTQ on the Linux GPU container in C5 and compare its Q/DQ placement, calibrators and accuracy with the ORT models from C3 (same calibration manifest, same scoring sets).
- **Configuration-to-configuration noise in sensitivity** (from C3, D-017): the thread-count noise floor understates how much a 100-image score moves between configurations (keeping some groups in float made scores worse by up to 0.125 points). Estimate it directly, e.g. a bootstrap over images of each configuration's delta, and base the `distinguishable` flag on that.
- **Calibration sampling variance** (from C3, D-019): calibrate DeepLab on several seeded 200-image train subsets and report the spread of its INT8 mIoU, rather than one sample per setting.
- **Recover DeepLab's stem in INT8** (from C3): instead of keeping `bb.stem_16` in float, try cross-layer equalization or bias correction (Nagel et al., 2019, "Data-Free Quantization") on the first depthwise block, whose per-channel activation ranges a per-tensor scale handles badly. Hypothesis only; not measured here.
- **Collapse repeated validator findings** (from C3): a uint8 quant config gives one `VALIDATE_QDQ_DTYPE` naming the cause, then one `VALIDATE_OP_RESTRICTION` per Q/DQ node for its non-zero zero point (172 for DeepLab, 260 for SegFormer). Grouping findings with the same code and cause, or suppressing the symptom when the cause is reported, would make reports easier for the triage tool to read.
